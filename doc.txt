1. WHAT IT IS
-------------
Desktop player for YouTube / YouTube Music in Python + Tkinter.
- Searches songs, plays streaming audio (~3 s) with fallback to download.
- Links to your Google account via cookiesYT.json, permanent OAuth, or
  browser session (Chrome/Edge/Brave...). Without account it works as guest
  (search + public URLs).
- Ultra-customizable: background color/gradient/image/VIDEO, PNG-shaped
  buttons, image icons, transparency, frameless custom title bar, floating
  stickers, movable/resizable video panel, draggable sidebar order,
  persistent volume, progressive lists.
- No visible console window (hidden on Windows).
- NO local song storage: no local favorites, no local lists. Favorites =
  YouTube Music "Liked songs" (rate_song API); playlists = YouTube Music
  playlists only.

2. LAUNCH
---------
- `python start.py`          -> opens the player (hides console unless
  --consola). This is the canonical entry point.
- `python Iniciar.py`        -> legacy alias, does exactly the same
  (kept so old shortcuts keep working).
- `pythonw start.pyw` / `pythonw Iniciar.pyw` (or double-click them)
  -> no console at all.
- `python start.py --selftest` -> 8 automatic checks (deps, cookies,
  theme, client, ffmpeg stream, audio engine, OAuth/session, UI import).
  It NEVER signs in: the client is built with `use_account=False` (guest),
  which skips OAuth, the browser session and the cookie file, so test
  queries cannot end up in the real account's YouTube Music history.
- `python start.py --selftest --offline` -> same checks with no network
  calls (skips the search and the ffmpeg stream check).
- `python start.py --reset` -> resets config/theme.json to defaults.
- `python start.py --consola` / `--show-console` -> force showing console.
- `PrerequisitesInstalation.bat` (double-click on a fresh Windows) installs
  Python (winget fallback), upgrades pip, installs requirements.txt and
  verifies imports.

Flow: Iniciar.py main() -> ensure_dirs -> crash log -> console hide/relay
to pythonw (no window ever shows) -> ThemeManager -> YouTubeClient ->
PlayerEngine -> MainWindow.run(). Fatal errors go to cache/crash.log;
stdout goes to cache/stdout.log when console hidden.

4. DEPENDENCIES AND BACKENDS
----------------------------
- yt-dlp: search, stream info, download, browser cookies.
- ytmusicapi: playlists, liked songs, search, OAuth, radio, related, album,
  artist, lyrics.
- pygame.mixer: local fallback audio (MP3). Buffer 512, 44100 Hz.
- sounddevice + numpy + ffmpeg (imageio-ffmpeg): online streaming without
  downloading.
- PIL/Pillow: backgrounds, thumbnails, button shapes, icons, video frames,
  stickers.
- imageio: background/video frame reading, GIFs.
- selenium: direct Google login (auto chromedriver).
- VLC (optional): detected but not used as main backend (pygame is main).

5. THEME SYSTEM (config/theme.json + themes/<name>/)
----------------------------------------------------
ThemeManager.load() merges defaults with the loaded file, so old themes
auto-migrate (new keys appear without erasing customization).
get(*keys, default) / set(value,*keys) -> save() / reset() / save().

Every user-visible string is English. Internal schema keys stay in Spanish
on purpose (renaming them would silently drop existing customization);
new code uses .get() with defaults.

Theme packages live in themes/<name>/ and contain theme.json (+ assets/).
Asset paths inside a package are stored RELATIVE (assets/ccc...png) and the
files are copied into themes/<name>/assets/ on save; at load they are
resolved back to absolute paths. A package snapshots ABSOLUTELY ALL
graphical settings:

- ventana: title, size, transparency, always on top, custom title bar,
  hide console.
- fondo: mode (color|gradient|image|video), colors, gradient direction,
  image/video paths, overlay opacity.
- botones: size, shape (round|square|custom PNG), custom PNG path, colors,
  border, radius, spacing.
- iconos: 16 keys (play, pause, prev, next, shuffle x2, loop x3, fav x2,
  volume, search, settings, customize, playlist, close) + icon font size;
  each is a text glyph or an image path. The DEFAULT set is deliberately
  MONOCHROME (▶ ▌▌ ◀◀ ▶▶ ⇄ ↻ ↻1 ♡ ♥ ♪ ⌕ ⚙ ◐ ☰ ✕), never a colour emoji.
- texto: font family, custom .ttf/.otf path, sizes, 4 colors.
- lista: colors, hover/active, thumbnails on/off, thumbnail size,
  background transparency vs. the wallpaper, progressive batch size.
- fondos_secciones: per section (Search, Playlists, Liked, Queue):
  inherit | color | image | video.
- fondos_botones: per sidebar button (inherit | color | image).
- fondos_paneles: per panel (top bar, sidebar, playlist list, player,
  progress, volume).
- video_panel: visible, dx/dy (relative to main window, may be outside),
  w, h, fps (1-30).
- sidebar_orden: ordered section keys.
- stickers: [{path, dx, dy, w, h}] — floating images following the window.
- reproductor: default volume, default loop, default shuffle, autoplay,
  audio quality, cache MB, notifications, save volume.
- cuenta: cookies JSON path, use cookies, session source (file|browser),
  browser.

6. YOUTUBE CLIENT (app/youtube_client.py)
-----------------------------------------
YouTubeClient(cookies_json_path, cache_dir, use_cookies,
              session_source, browser)
Attributes: cookies, cookie_header, netscape_path, auth_path, oauth_path,
oauth_creds_path, ytmusic, authenticated, auth_method (oauth|cookies|none),
account_label, last_error, stream/video caches, lock.

PLAYER_CLIENTS = ["android","web","mweb"] to avoid "reload page".
Session: _load_cookies / reload_cookies / import_login_cookies /
_read_navegador / _apply_navegador_cookies / _maybe_heal_session
(re-reads browser every 120 s when source=browser) / _auth_call.
OAuth: _load_oauth_creds / save_oauth_creds / get_oauth_creds_saved /
oauth_linked / disconnect_oauth / finish_oauth_device (device flow).
_init_ytmusic: 0) OAuth if oauth.json+creds and get_account_info OK;
1) browser.json if account info OK else "Session expired";
2) YTMusic() guest.

Library: get_library_playlists(limit) -> [{id,title,count,thumbnails,source}];
get_liked_songs(limit) -> [norm]; get_playlist_tracks(pid,limit)
(ytmusicapi + yt-dlp flat fallback); fetch_progressive(kind, identifier,
limits, on_batch, should_stop): kind=liked|playlist|library; increasing
limits (100,300,800,2000,5000); on_batch(batch, is_final) per step; stops
when the list stops growing. Runs in a thread, never blocks UI.

Writing (need authenticated session): add_to_playlist(pid, video_ids);
create_playlist(title, video_ids, description, private) -> pid;
like_song(video_id, like) via rate_song(LIKE/INDIFFERENT);
dislike_song(video_id, dislike) via rate_song(DISLIKE);
remove_from_playlist(pid, tracks) (needs setVideoId, own playlists only);
delete_playlist(pid); rename_playlist(pid, title).

Streams: get_stream_info(vid) (cache 3 h, bestaudio, best abr);
get_video_info(vid) (cache, mp4 ~360p for panel); download_audio(vid,hook)
(reuses MP3 cache, converts via ffmpeg).

YT Music menu options (right-click on any song / playlist):
- get_watch_tracks(video_id, radio=False, limit=25): "Up next"
- start_radio(video_id, limit=25): YT Music radio (varies every time)
- get_up_next(video_id, limit=25)
- get_song_related(video_id, limit=20)
- get_album_tracks(browse_id) -> (title, tracks); fallback: search by name
- get_artist_info(artist_id); get_artist_top_tracks(artist_id, limit=20)
- get_lyrics_text(video_id) -> (lyrics, source) via watch playlist +
  get_lyrics
- get_song_details(video_id) -> raw get_song dict
- _norm_track(t): videoId, title, artist, artistIds, album, albumId,
  thumbnail, duration, duration_sec, setVideoId, browseId, likeStatus

No radio/startRadio/get_album/get_artist in ytmusicapi 1.12.3? They exist;
all are implemented above.

Search returns SONGS AND VIDEOS together, with no distinction in the rows
(every row is the same playable item, thumbnail, duration, context menu).
THREE sources are queried IN PARALLEL and merged, so a song shelf can never
hide a video:
1) YT Music filter="songs",
2) YT Music filter="videos" (one unfiltered YT Music search buries videos
   under albums, artists and podcasts),
3) REAL YouTube via InnerTube WEB search (_search_youtube_web, client WEB
   then TVHTML5, parses twoColumnSearchResultsRenderer -> videoRenderer).
   This one is essential: yt-dlp's ytsearch is BLOCKED here (0 entries for
   every query and every player client) and YT Music only knows its own
   music catalogue, so a doujin/cover/video outside it (e.g.
   "touhou maiden de kuwabarakuwabara") used to be unreachable - searching
   its exact title showed unrelated songs and no video at all.
Videos are the two video sources alternating (YT Music shelf + real YouTube,
both represented, deduped by videoId), then rows are merged by
_merge_search_kinds: a few songs head start (typing a name usually means
the song), then 1 song : 1 video, leftovers always kept. Total latency
~1 s (parallel). Last resort: yt-dlp. The section title shows the split
("Results: X • 17 songs • 13 videos") so the mix is visible at a glance.

Which copy is running: Settings > "RUNNING FROM" prints the absolute folder
plus the modification time of app/ui_main.py and app/youtube_client.py. The
user keeps numbered copies under Desktop\CopiasOpenYTPlayer, so a stale
copy is the classic "my change did nothing" trap.

7. PLAYER ENGINE (app/player_engine.py)
---------------------------------------
PlayerEngine(client, volume, loop_mode, shuffle,
             on_track_change, on_state_change)
State: stopped|loading|playing|paused. queue:[], index, loop_mode
(off|all|one), shuffle, volume 0-100, current, duration_sec, stream|pygame
backends.
- set_queue(tracks, start=0, autoplay=True): full queue; play from position
  (uses the complete list, not just visible rows).
- cycle_loop(): off > all > one > off. set_shuffle(on).
- play_at(pos): stop + load in thread (_load_and_play):
  get_stream_info -> StreamPlayer.play(audio_url) -> monitor;
  fallback download_audio + pygame.mixer; auto-skip next on failure
  (0.5 s anti-cascade sleep).
  SKIP SAFETY (no x2 speed, no frozen UI): play_at() never waits for the
  previous loader (that used to block the UI for up to 2 s per skip). Each
  call increments a generation number; only the newest generation may open
  audio, older loaders return before touching the streamer, and the newest
  loader waits for the previous one inside its own background thread. One
  stream at a time, no matter how fast the user skips.
- pause/resume/toggle/next/prev/stop/seek(seconds) (stream seek real;
  file best-effort). set_volume applies to streamer + pygame.
- get_position(): streamer pos / pygame get_pos / time since play start;
  paused returns _paused_pos.
- _monitor_loop() each 0.5 s -> _on_track_end() (loop one/all).
Volume persists: slider moves -> player + debounced save to
reproductor.volumen_defecto; saved on close.

-------------------------------
MainWindow(theme, client, player). Tk root, WM_DELETE -> on_close.
Build: bg_label + main container (dark bg from first frame, no white flash)
+ custom title bar (title, ✕/▢/─ buttons, native Windows drag via

Body: sidebar (190 px, draggable button order: 🔍 Search / 📃 Playlists /
♥ Liked / ⏳ Queue; + New YT playlist; playlist library box) + list panel
(scrollable canvas with rows, "Show more" button, infinite scroll only when
near bottom and real scroll exists).
Player bar: thumbnail (= play button, ▶ overlay) + song title + progress
Scale (click anywhere to jump to that time; drag also works) + times +
controls (prev, play/pause, next, shuffle, loop, liked) + volume
(−/+ buttons, 0.2-step slider, icon, label).
Status bar at bottom.

Rows (songs): square thumbnail (cover, no distortion; cache by URL+size),
title — artist, duration. No inline buttons anymore: SINGLE click anywhere
on the row (title, thumbnail, duration or background) plays it; dragging
the row reorders it (even across the recommendations separator); a single
click on a channel name opens that channel. RIGHT-CLICK opens the full YT Music menu:
Play / Play next / Add to queue / Start radio / Up next (YT Music) /
Related songs / Like / Dislike / Save to YT playlist / New YT playlist /
Remove from this playlist / View album / View artist / View lyrics /
Song details / Copy YouTube URL / Open in YouTube. Playlists rows: double-
click or right-click (Open / Playlist radio / Rename / Delete / Copy URL).

FINAL LIST BEHAVIOR (songs, queue, recommendations)
- ONE CLICK = PLAY. A single click anywhere on a song row (title,
  thumbnail, duration or background) plays that song immediately. There is
  no double-click requirement anywhere in the app.
- ONE CLICK ON A CHANNEL = OPEN THAT CHANNEL. Every artist of a
  multi-artist song gets its own channel label with its own channelId. If
  a track has no channelId, the app asks YouTube for the uploader and opens
  that channel anyway.
- DRAG = REORDER. Press and move more than 4 px: the dragged row is
  repainted live in the slot under the pointer and dropped there. ANY song
  can be dragged from ANY position to ANY position, including across the
  recommendations separator (playlist songs and recommendations are
  interchangeable). There are no ▲/▼ buttons: drag is the only reordering
  method, and it works in playlists, albums, other users' playlists, the
  queue and the recommendation block.
- REORDERING IS SESSION-ONLY: it never modifies nor saves any YouTube
  playlist or album, and nothing is written to disk.
- PLAYING A SONG loads the WHOLE visible list (playlist + recommendations)
  into the queue and jumps to the Queue section, so the user can reorder
  the exact queue that is playing.
- THE QUEUE ALWAYS SHOWS WHAT IS PLAYING: current_list_full and
  player.queue are the same order. Entering or leaving the queue never
  duplicates the recommendations (the old behaviour appended them twice).
- LOOP OFF + playlist/album: a separator bar appears after the playlist
  songs and the recommendations are painted underneath. When the playlist
  ends, playback continues with the FIRST recommendation, then with the
  next one, in the visual order. Every recommendation that starts playing
  moves ABOVE the separator, so the played ones pile up above it and the
  pending ones stay below.
- With shuffle OFF, the song right after the playlist is always the first
  recommendation.
- Dragging never loses the songs that are not rendered yet ("Show more"
  not clicked): they are kept at the end of the list.
- Turning loop ON removes the separator AND the recommendations from the
  session list and from the queue.

Favorites = YT Music "Liked songs" (progressive load, cache _liked_ids to
paint ♥/♡ without network per row). Sign-in required to Like.

Video panel (Toplevel, transient of main window, NO -topmost: stays above
the app but never over other programs; no more flicker over foreign
windows): title bar, cover/video, hide/expand buttons, resize grip.
Draggable anywhere (even outside the window), follows the main window.
Show/hide/center/FPS from Customize > Video. Cover loads immediately

Stickers: floating Toplevels (transient, no topmost), follow the main

Video + stickers stacking: principal < video < stickers, re-affirmed only

10. PERFORMANCE
---------------
- First batch 100 fast + render 80 rows: UI answers <2 s even with 2000
  liked songs; rest arrives in background.
- VIRTUALIZED LIST: the rows on screen are a WINDOW of the list, never the
  whole list. current_list_full holds every song (that is the data, the
  queue and the playback order), but only ~80 row widgets are alive at a
  time (lote_progresivo). The recommendations are always painted, they are
  few.
- HARD CAP of live rows (MAX_LIVE_ROWS = 200): when "Show more" would paint
  more than that, the window moves forward instead of building thousands
  of widgets. A 10 000 song playlist therefore keeps ~160 rows alive,
  loads in half a second and never freezes.
- The rows are re-used (recycled) when the list pages: the widgets are
  updated instead of being destroyed (destroying hundreds of Tk rows took
  a whole second).
- The background picture of a row (list transparency) only exists for the
  rows on screen; the others are freed when they scroll out.
- The thumbnail cache is capped too (_trim_thumb_cache, 900 images), so
  scrolling a long list cannot fill the memory with pictures.
- fetch_progressive stops when the list stops growing.
- Autocheck only with real scroll (no eager preload).
- Background resize debounce 600 ms + thread. Video panel fixed FPS.
- Failures never hang: daemon threads, try/except everywhere, _call_ui is
  the only UI-thread bridge (never touch Tk from threads).

12. KNOWN ISSUES
----------------
- "Session expired": old cookies. Fix: refresh cookiesYT.json (auto-reloads),
  use browser session, OAuth permanent, or direct Google login.
- "Only removable from your own playlists": YT does not allow removing from
  Liked/automatic playlists (missing setVideoId).
- Stream without data / expired URL: auto-skip to next.
- No audio device: stream fails -> fallback download + pygame.
- Window frame: on Windows the native caption is removed; a 1 px DWM border
  remains and is tinted to the theme color (DWMWA_BORDER_COLOR/CAPTION_COLOR).
  On old Windows it may stay white/transparent.
- Video black: no video_url (restricted) -> cover is expected.
- Stickers do not show over other apps (by design: transient of the app,
  not topmost). Move them or bring the app to front.

13. FOR THE NEXT AI / MAINTAINER
--------------------------------
- Respect ThemeManager._merge; new keys with defaults in DEFAULT_THEME, or
  old UI crashes with KeyError (use .get with default).
- NEVER touch Tk from threads: use _call_ui() + _pump_ui().
- _progressive_token cancels obsolete loads; copy it at thread start and
  check each batch + should_stop.
- current_list vs current_list_full: play/queue ALWAYS full; render only
  visible. Do not mix.
- Save geometries/volume/stickers on release or close, not on every motion.
- Video panel is a transient Toplevel (no topmost); stickers too. Never set
  -topmost again (that caused flicker over other windows).
- Console: relays to pythonw on first run if ocultar_consola; never print
  blocking input() without try.
- After editing ui_main.py: py_compile + --selftest + smoke UI test.
